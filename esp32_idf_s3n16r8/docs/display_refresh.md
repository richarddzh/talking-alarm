# TFT 无闪烁刷新设计

## 问题

旧实现每次内容变化都把 320×240 画面逐行完整写入 ST7789。屏幕不会被
软件主动关背光或清成黑色，但一次全屏 RGB565 传输约 153.6 KB；显示控制器
扫描期间看到逐行更新边界时，会表现为亮度跳动或闪烁。

## 方案

`ui_screen.c` 在 PSRAM 中保留当前帧和上一帧：

1. 首帧完整刷新；
2. 后续逐行比较 4-bit framebuffer；
3. 小范围变化只提交每个变化行的最小水平区间；
4. 变化超过帧缓冲三分之一时，退化为一次完整刷新；
5. SPI 成功后才更新上一帧副本。

`st7789_show_indexed4_region()` 接收原始 framebuffer 坐标并设置对应 LCD
窗口，避免为了局部刷新复制临时矩形。该方案减少聊天状态、时钟、焦点和
游戏移动时的 SPI 数据量，也降低 Core 0 占用，不改变 Core 1 音频任务。

## 限制

该显示模块没有连接 ST7789 TE 同步引脚，因此无法与面板扫描线做硬件级
垂直同步。局部刷新可消除绝大多数肉眼可见的整屏闪烁；若硬件实测仍存在
撕裂，后续可连接 TE 引脚并在区域提交前等待同步信号。
