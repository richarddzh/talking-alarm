# 小鱼缸与番茄时钟

两个 App 使用 `gui_app_t` 注册，不直接读取 GPIO，不创建额外高优先级任务。
启动器保持三列、两行可视窗口，焦点进入第三行时自动滚动；当前共七个 App。

## 小鱼缸

- 默认 12 条，范围 1–32；底部「减少」「增加」每次调整 1 条。
- 「暂停／继续」控制游动；左右移动按钮焦点，确认执行，上下可到首页。
- 橙色和紫色鱼均由用户参考图抠出，保留轮廓、眼睛、鳍和花纹，只随水平方向
  镜像，不用程序几何图形重画鱼身。
- Boids 同时使用邻域分离、速度对齐、中心聚合及柔性避墙；先用旧状态计算
  所有鱼的下一状态，再统一提交，避免数组顺序影响邻居计算。
- Core 0 当前 App `tick()` 约每 66 ms 更新一次，速度限制在 12–32 px/s。
  单次积分步长上限 100 ms，网络阻塞后不补跑大量模拟步。
- 模拟双缓冲和 RGB565 合成区在进入时一次分配到 PSRAM，退出时释放；
  约 80.5 KB，不在每帧分配内存。分配失败记录错误并显示重试提示。
- 鱼先在 PSRAM 合成完整的 308×129 水域，再通过现有内部 640 B SPI 行缓冲
  提交，透明鱼不会擦掉相互重叠的鱼，不增加内部 DMA 大缓冲。
- 离开、自动息屏或休眠会退出鱼缸并释放 PSRAM；本次开机调整的鱼数保留，
  不写入文件系统。重新进入重新生成位置。

## 番茄时钟

- 专注 25 分钟 → 短休息 5 分钟；每完成第 4 次专注改为长休息 15 分钟。
  阶段到期自动切换，长休息后继续专注。
- 「开始／暂停」保留当前阶段的剩余时间；「重置」停止并返回首轮 25 分钟。
- 左侧使用用户提供的番茄闹钟图作背景，保留外壳和配色。按用户要求，
  表盘内的原短线刻度与固定指针替换为 1–12 数字及时、分、秒针；
  下方显示真实 `HH:MM:SS`。
- 右侧显示阶段、`MM:SS` 倒计时、进度及累计完成次数；原图番茄表情另以
  小图展示。没有 RTC/网络有效时间时显示「等待校时」，倒计时仍可运行。
- 倒计时使用 `esp_timer` 单调时钟 deadline，不依赖系统校时、不按帧减秒。
  主循环 `app_pomodoro_update()` 独立于 GUI 当前 App 执行，所以切换页面、
  打开启动器、息屏都不停止计时；只在当前页每秒刷新一次画面。
- 延迟跨越多个阶段时按原 deadline 推进；跨越完整 130 分钟周期可批量推进，
  只保留最新阶段的一条待播报消息，不堆积过时提醒。
- 自动休眠调用 `app_pomodoro_pause_for_sleep()`，保留剩余时间并取消待播报，
  唤醒后手动继续。这保持“休眠仅保留整点报时”的原有规则。
- 倒计时和累计次数仅保存在当前开机 RAM，重启后回到初始状态。

## 豆包语音提醒

开始/继续时播报「开始工作啦」或「开始休息啦」；自动边界使用合并短句：
「工作结束啦，开始休息……」「休息好啦，开始工作……」；长休息明确说明
十五分钟。调用 `chime_player_start_text()` 直接使用豆包 TTS，不调用 Agent。

App 只保存静态短句指针；由 `app_main` 检查策略并提交现有 Chime worker：

- 复用 `AUDIO_OWNER_CHIME`、Core 0 PSRAM 栈及共享 PCM ring；
  Core 1 继续仅服务实时 I2S，不在 `tick/render` 中联网。
- 安静模式、配置模式和休眠禁止播报，并显示原因。
- Wi-Fi 未连接或 API 配置未就绪时显示不可用、记录日志；倒计时照常运行。
- 录音、电台或其他音频 busy 时不抢占，最多等待 30 秒；过期后显示超时，
  计时不回退，也不在很久以后播报旧阶段。
- TTS 接受后显示播报中，结束/失败反馈到 App；失败不伪装成播报成功。
- 不唤醒息屏显示，不取消原有音频 owner，不从其他任务关闭网络句柄。

## 素材处理与授权边界

本实现最终使用用户四张附件，不再使用网上下载的替代图案。完整原图保存在
`main/assets/small_apps/references/`；源图不覆盖、不删除水印、不宣称原创。
分发者须确认有权使用这些用户提供素材。

派生图只做背景连通抠图、3×3 中值滤波、96 色轻度归并、弱锐化、等比缩放
和透明留边。番茄底部灰白页面条从主体 alpha 排除；眼睛、腮红、嘴巴与花纹
不重绘。时钟原图将表盘内部透明化，用数字刻度和真实时间指针替换。

重建命令和依赖见
[`python_scripts/prepare_app_art/README.md`](../../python_scripts/prepare_app_art/README.md)。
结果包括可检查 PNG、启动器 RGB565/alpha 和 `small_apps_art.h`；
设备运行时不解码 PNG，图案常量在 Flash，不占同等大小的常驻 RAM。

## 图层接入与验证

`gui_app_t.render()` 先画索引画布，`render_overlay()` 可选地在 `ui_flush()`
后提交原图全彩图层。使用此回调的 App 在切换离开时由 Shell 失效旧画面，
防止全彩精灵残留。动态叠加必须有正确的背景/合成策略，不能让透明像素清除
先画的精灵，也不能把整个 RGB565 场景放进内部 SRAM。

从仓库根目录运行：

```powershell
python tools\test_small_apps.py --clang (Get-Command clang).Source
```

三项针对性检查编译生产 App/GUI 代码：计时边界、长休息/暂停/休眠和长延迟；
鱼数/速度/边界和 PSRAM 释放；第七个 App 的启动器访问。
可加 `--preview-dir <目录>` 输出生产绘制函数生成的 PNG，需 Pillow。
最终仍需实机验证按键、连续动画、RTC 指针、豆包开播及阶段到期语音。

本次最终固件已通过 COM3 烧录校验并正常启动；启动日志内部空闲
`int=176395 B`。固件大小 `0x32ccb0`，4 MB App 分区剩余约 21%。
计时边界使用生产代码检查；完整 25 分钟实际等待和豆包听音不以主机预览代替。

所有后续修改遵守 [memory_analysis.md](memory_analysis.md) 的内存和音频所有权约定。
