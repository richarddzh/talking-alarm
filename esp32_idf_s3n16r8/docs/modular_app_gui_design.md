# 模块化 App GUI 设计

## 目标

把当前单页面闹钟界面改造成可扩展的设备级 App 系统：

- 开机默认进入“闲聊闹钟” App。
- 通过底部 Home 按钮进入主导航。
- 主导航以手机桌面风格显示 App 图标和文字标签。
- 选中项显示外框。
- 底部固定状态栏：左侧 Home 图标，右侧时间和 Wi-Fi 状态。
- 主按钮和摇杆按下默认执行相同的“确认”动作。
- App 可以接管特殊输入，例如闲聊闹钟 App 的主按钮长按录音。
- 新 App 通过注册描述符加入，不修改 GUI 核心。

当前包含：

1. 闲聊闹钟
2. 设置
3. 俄罗斯方块
4. 贪吃蛇

## 显示模型

ST7789 物理分辨率为 320×240。GUI 直接使用 **320×240 原生分辨率**，
不再缩放低分辨率画面。

画布采用 4-bit 索引色，每个像素可使用 16 个主题颜色，每字节保存两个
像素。完整 framebuffer 为 38,400 字节，在 `ui_init()` 中从 8 MB PSRAM
分配，避免挤占 Wi-Fi、TLS、I2S DMA 所需的内部 SRAM。提交画面时，
ST7789 驱动逐行把索引色转换为 RGB565，只需要一个 640 字节 DMA 行缓冲。

中文界面使用独立的 `font_zh16.[ch]` 和
`assets/unifont_bmp16.bin` 点阵字体文件。字体从 GNU Unifont 16.0.04
生成完整 BMP 16×16 字形表，支持任意常用中文对话的 UTF-8 查找；ASCII
继续使用现有 5×7 字体。字体表约 2 MB，保存在 16 MB Flash，不占用运行时
PSRAM 或内部 SRAM。

逻辑区域：

| 区域 | 坐标 | 用途 |
|---|---:|---|
| App 内容区 | `x=0..319, y=0..205` | App 页面或主导航 |
| 分隔线 | `y=206..207` | 内容与状态栏分隔 |
| 状态栏 | `x=0..319, y=208..239` | Home、时间、Wi-Fi |

状态栏始终由 GUI 核心绘制，App 不直接覆盖状态栏。

## 输入映射

当前硬件代码提供主按钮及 `B/X/Y` 三个摇杆相关 GPIO。首期映射如下：

| 硬件输入 | GUI 语义 |
|---|---|
| B | 摇杆按下/确认 |
| X 模拟轴 | 左/右移动焦点 |
| Y 模拟轴 | 上/下移动焦点 |
| 主按钮短按 | 确认 |
| 主按钮长按 | App 特殊动作；闲聊闹钟中为按住录音 |

焦点统一包含底部 Home。每个 App 使用 `gui_focus_node_t` 显式声明控件在
左、右、上、下四个方向的目标索引，支持不规则二维布局。

主导航中的 App 图标也遵循同一焦点循环。确认 Home 后进入主导航；确认
App 图标后打开对应 App。

X/Y 已由 ADC 输入适配层映射为 `UP/DOWN/LEFT/RIGHT`。游戏 App 可以通过
可选输入处理回调接管方向键，不必改变系统导航。

## 模块划分

### `ui_screen.[ch]`

底层 16 色索引画布：

- 清屏、像素、矩形、文字、线条和简单图标绘制。
- 提供背景、面板、焦点、主色、成功、警告等统一主题颜色。
- 将 PSRAM 中的完整 framebuffer 逐行转换并提交到 ST7789。
- 不知道 App、Wi-Fi 或业务状态。

### `gui_shell.[ch]`

系统 GUI 核心：

- 保存当前页面（主导航或 App）。
- 保存当前焦点。
- 注册 App 描述符。
- 执行默认焦点移动和确认路由。
- 绘制主导航、选中框和底部状态栏。
- 把 App 动作转换成业务层可处理的 `gui_action_t`。

### `app_chat_alarm.[ch]`

闲聊闹钟 App：

- 显示日期、时钟、语音表情、音频/网络状态。
- 提供“闲聊/报时”确认动作。
- 主按钮长按录音仍由业务编排层执行，但只在本 App 打开时生效。

### `app_settings.[ch]`

设置 App：

- 安静模式开关。
- Wi-Fi 配置 AP 开关。
- 立即网络校时。

### `app_main.c`

设备业务编排：

- 采集按钮事件并转换为 GUI 输入。
- 执行 GUI 返回的业务动作。
- 管理 Wi-Fi、RTC、语音、报时和配置 AP。
- 构造只读 `gui_model_t`，不负责具体页面排版。

## App 注册接口

每个 App 提供一个 `gui_app_t` 描述符：

```c
typedef struct {
    const char *id;
    const char *label;
    gui_icon_t icon;
    uint8_t focus_count;
    void (*enter)(void);
    void (*exit)(void);
    gui_action_t (*tick)(int64_t now_ms);
    void (*render)(const gui_model_t *model, int focused_item);
    gui_action_t (*activate)(uint8_t item);
    bool (*handle_input)(gui_input_t input, gui_action_t *action);
} gui_app_t;
```

- `id` 是稳定标识，不依赖显示名称。
- `label` 是主导航文字。
- `icon` 由 GUI 核心绘制，后续可扩展位图图标。
- `focus_count` 声明 App 的默认可聚焦控件数量。
- `enter/exit` 隔离 App 激活和离开时的资源与回调。
- `tick` 是 App 独立事件循环；只有当前打开的 App 会被调用。
- `render` 只绘制内容区。
- `activate` 处理默认确认动作。
- `handle_input` 可选；游戏、播放器等复杂 App 可接管方向输入。

加入新 App 的步骤：

1. 新建独立的 `app_xxx.[ch]`。
2. 实现描述符及私有状态。
3. 在 App 注册表追加描述符。
4. 不修改状态栏、主导航和公共焦点逻辑。

## 首期页面

### 闲聊闹钟

- 页面采用聊天软件布局，左右气泡显示最近三条消息。
- 内存中保存最近六条用户/助手消息，即最近三轮对话。
- ASR 文本显示为右侧用户气泡，Agent 回复显示为左侧助手气泡。
- 顶部显示 App 名称和录音/等待/播放状态。
- 一个可聚焦的“CHAT / HOLD TALK”动作卡：
  - 短按确认触发一次闲聊/报时。
  - 主按钮长按开始录音，松开后识别、问答和播放。

### 设置

竖向三项：

1. Quiet mode：切换自动报时静音。
2. WiFi setup：开启或关闭 SoftAP 配网页。
3. Sync time：立即通过 Wi-Fi 校时并写入 DS3231。

每项使用选中外框，状态值显示在右侧。

### 主导航

首期显示两个 App 图标，横向排列：

```text
+---------+   +---------+
|  clock  |   |  gear   |
|  Chat   |   |Settings |
+---------+   +---------+
```

未来五个 App 使用每行三个图标的网格排列；注册表顺序决定桌面顺序，
GUI 核心负责换行。

## 状态和刷新

- GUI 使用完整重绘，不保留控件级脏矩形。
- RTC 每秒变化、Wi-Fi 状态变化、语音状态变化或焦点变化时重绘。
- App 只读取 `gui_model_t` 快照，避免直接访问跨任务业务状态。
- `gui_shell_tick()` 只调用当前 App 的 `tick()`；主导航页面不调用任何
  App 事件循环。
- 闲聊闹钟的录音 pump 和超时处理只存在于 `app_chat_alarm.c`。
- 设置 App 当前没有周期任务，因此 `tick = NULL`。
- 后续游戏和网络电台拥有各自的 `tick()`，彼此不会同时运行或修改状态。
- GUI 绘制仍在 Core 0；音频 DMA 和 I2S 继续在 Core 1。

## 错误与兼容策略

- App 返回动作，由 `app_main.c` 执行并将结果写入统一状态消息。
- Wi-Fi、音频或 RTC 失败不会让 GUI 核心进入业务错误状态。
- 配置 AP 期间仍保留 GUI 和设置入口，但暂停原有联网、报时和语音后台任务。
- 首期不持久化当前 App 和焦点；重启始终打开闲聊闹钟。
