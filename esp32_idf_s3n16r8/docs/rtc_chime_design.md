# RTC、随机发言与整点报时设计

本文按当前代码说明 DS3231 时钟源、自动 chime 调度和实际播放链路。

## 时间来源

- DS3231 独占 I2C 总线：SDA `GPIO8`、SCL `GPIO9`，地址 `0x68`。
- 主循环每 250 ms 读取一次 DS3231，TFT 显示和 chime 调度都使用该本地时间。
- 启动时若有 Wi-Fi 凭据，会联网校时并把结果写入 DS3231。
- 后续网络校时间隔由 `APP_TIME_REFRESH_MS` 控制，当前为 24 小时；音频活动
  期间会推迟校时。
- 网络校时使用 `esp_netif_sntp` 访问 `ntp.aliyun.com`，取得 UTC 后按
  `CST-8` 转换为中国标准时间，不再依赖 HTTP 时间服务。
- 单按钮没有手动校时手势。

完整协议、时区和失败行为见
[`sntp_time_sync.md`](sntp_time_sync.md)。

RTC 时间无效时不能生成自动调度，但不影响用户长按发起语音对话。

## 三种 chime 入口

| 入口 | 时间限制 | 传给 Agent 的内容 |
|---|---|---|
| 闲聊闹钟 App 确认 | 无工作时段限制 | 从 23 条随机提示词中随机选择一条 |
| 自动随机发言 | 当前禁用，每小时规划 0 次 | 与手动闲聊相同的随机提示词池 |
| 自动整点报时 | `07:00` 至 `23:00`，包含两端 | `现在是<12 小时制时间>。请你整点报时。` |

三种入口都通过 `chime_player` 在 Core 0 调用豆包 Agent，取得文本后再调用
豆包 TTS，PCM 交给 Core 1 的音频任务播放。固件没有内置固定报时音频。

## 自动整点报时

每个有效小时开始时，调度器设置一个 `hourly_pending` 标志。有效小时为
`07:00`、`08:00`……`23:00`。

- 尝试窗口是整点后的前 5 分钟，即 `HH:00:00 <= time < HH:05:00`。
- 整点任务优先于该小时的随机任务。
- 如果语音录制、其它 chime 或音频 I/O 正忙，会在窗口内继续等待并重试。
- 到 `HH:05:00` 仍未成功启动，则本小时报时作废，不再补报。
- 设备在 `HH:05:00` 之后启动或恢复出有效时间时，也不会补报该小时。
- 一旦 `chime_player_start()` 接受任务，就视为本小时已触发；之后即使
  Agent 或 TTS 请求失败，也不会自动重试。

传给 Agent 的时间使用 12 小时制和 `AM`/`PM`，例如：

```text
现在是7:00 AM。请你整点报时。
现在是12:00 PM。请你整点报时。
现在是11:00 PM。请你整点报时。
```

## 自动随机发言

自动随机发言当前通过 `RANDOM_CHIME_COUNT = 0` 暂时禁用，因此进入新小时
时不会生成目标时刻，也不会自动调用 Agent 或 TTS。手动闲聊不受
影响。

代码路径仍完整保留：

- `RANDOM_CHIME_SLOT_CAPACITY = 5` 保留 5 个槽位的静态存储，避免使用
  零长度数组；
- `plan_random_slots()` 仍由每小时调度刷新调用，数量为 0 时初始化槽位
  后直接返回；
- `maybe_dispatch_scheduled_chime()` 的随机槽位分发循环仍保留；
- 将 `RANDOM_CHIME_COUNT` 改为 `1`–`5` 即可恢复自动随机发言。

重新启用后的原有规划规则为：

- 时刻位于 `HH:05:00`（含）到 `HH:55:00`（不含）之间；
- 随机规划阶段要求任意两个时刻至少相隔 8 分钟；
- 最多尝试 200 次；极少数无法填满的情况使用分段回退值，因此 8 分钟
  是正常规划目标，不是回退路径的绝对保证；
- 设备在小时中途启动时，早于当前时间的槽位直接标记为已过，不会补播。

槽位到点后，如果音频忙或 Wi-Fi 暂时不可用，该槽位保持待触发状态，并在
同一小时内继续尝试。任务被 `chime_player_start()` 接受后即标记完成；
后续 Agent/TTS 失败不会重试。跨入下一小时后，旧小时未完成的随机槽位
会被新计划替换。

## 随机内容设计

`doubao_agent_client.c` 当前包含 23 条提示词，每次等概率选择一条。内容
类型包括：

- 时间、天气、吃饭、生活感受和明日计划；
- 笑话、绕口令、发呆休息；
- 地球、月亮、花朵、猫咪、骑行和作业；
- 上海、山东、超级马里奥；
- 当日新闻、上海热点、科技热点、游戏热点和热播电视剧。

提示词只是发送给豆包 Agent 的用户消息，最终播报文本由 Agent 动态生成，
因此随机发言的措辞、长度和事实内容并不固定。

## 安静模式

通过设置 App 切换安静模式。安静模式仅在
`maybe_dispatch_scheduled_chime()` 阶段暂停自动整点报时和自动随机发言：

- 手动闲聊仍可使用；
- 长按语音对话仍可使用；
- 整点任务超过前 5 分钟窗口后会被丢弃；
- 自动随机发言重新启用后，随机槽位不会因安静模式立即标记完成。同一
  小时内退出安静模式后，已到期槽位会继续尝试；
- 安静模式只保存在 RAM 中，重启后恢复为关闭。

## SoftAP 配置模式

SoftAP 配置模式暂停 RTC 刷新、自动 chime 调度、语音处理和 STA 重连，只
处理配置网页及按钮长按退出。退出配置模式后：

- 若仍在整点后 5 分钟内，可以建立本小时整点任务；
- 已经过去的随机槽位在重新规划时直接跳过；
- 若已超过整点后 5 分钟，不补报本小时整点。

## 关键实现位置

| 位置 | 职责 |
|---|---|
| `main/app_main.c:refresh_chime_schedule()` | 按小时建立整点和随机计划 |
| `main/app_main.c:plan_random_slots()` | 按配置数量生成随机发言时刻；当前数量为 0 |
| `main/app_main.c:maybe_dispatch_scheduled_chime()` | 安静模式、窗口、优先级和重试控制 |
| `main/app_main.c:trigger_chime()` | 音频空闲、Wi-Fi 和播放器启动检查 |
| `main/doubao_agent_client.c:doubao_agent_chime()` | 构造整点提示或选择随机提示词 |
| `main/chime_player.c` | Agent 文本获取及豆包 TTS 播放 |
