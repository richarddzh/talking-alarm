# 游戏 App 设计

## 公共约束

两个游戏均实现标准 `gui_app_t`，不访问 GPIO、不修改 Shell 全局状态，也
不创建额外高优先级任务。游戏状态仅在当前 App 的 `tick()` 更新；发生一步
状态变化时返回 `GUI_ACTION_REDRAW`，避免无变化时持续刷新 TFT。

游戏停止时 B/主按钮确认“开始”按钮。运行时 App 的 `handle_input()` 优先
消费方向事件，防止方向输入移动系统焦点或触发其它 App 动作。

## 俄罗斯方块

状态由 10×16 固定棋盘、当前形状、下一形状、旋转、位置、积分和消行数
组成。七种 Tetromino 使用独立颜色；碰撞检测同时覆盖边界和已固定方块。

显示分区：

- 左侧：100×160 游戏棋盘；
- 右侧：积分、消行数、下一形状；
- 右上：开始/重开按钮。

定时下降发生在 App `tick()`；消行后压缩棋盘并按一次清除行数增加积分。
方向键移动/软降，确认或向上执行旋转。

## 贪吃蛇

状态由蛇节点数组、当前/待生效方向、苹果、积分和移动时钟组成。每一步先
检查墙壁和自身碰撞，再移动；吃到红苹果后增长并重新选择未被蛇占用的位置。

渲染根据相邻节点关系动态选择视觉块：

- 中间节点：横向、纵向或四种转角；
- 头部：四种朝向，带白眼、黑眼珠和朝前的红舌头；
- 尾部：四种朝向，使用收尖几何；
- 身体：绿色圆角块，并带红色圆形斑点；
- 食物：红色圆苹果和绿色果梗。

方向更新拒绝立即 180° 掉头。移动间隔随得分下降但设有下限，保持可玩性
并避免 Core 0 被游戏循环占满。
